# brick-game-cpp

[![CI](https://github.com/YanaKris/brick-game/actions/workflows/ci.yml/badge.svg)](https://github.com/YanaKris/brick-game/actions/workflows/ci.yml)

**▶ [Играть онлайн](https://yanakris.github.io/brick-game/)** — веб-версия на WebAssembly (Emscripten),
собирается из того же ядра и публикуется на GitHub Pages.

Проект реализует игру «Змейка» на C++17 в объектно-ориентированной парадигме и объединяет её с
ранее написанным «Тетрисом» (на C) в единый набор из двух интерфейсов: консольного (ncurses) и
десктопного (Qt). Логика игры вынесена в отдельную библиотеку, интерфейсы подключаются к ней через
контроллеры по паттерну MVC.

## Что реализовано

- Библиотека логики «Змейки» на C++17 в пространстве имён `s21` (`src/brick_game/snake`).
- Десктопный графический интерфейс на **Qt** (`src/gui/desktop`) с меню выбора игры, поддерживающий
  и «Змейку», и «Тетрис».
- Консольный интерфейс на **ncurses** (`src/gui/cli`), перенесённый из BrickGame v1.0 и дополненный
  поддержкой «Змейки».
- Веб-версия на **WebAssembly** (`src/gui/web`): то же ядро через Emscripten, интерфейс на HTML5 Canvas,
  публикация на GitHub Pages (`make web`).
- «Тетрис» из BrickGame v1.0 (реализация на C, `src/brick_game/tetris`) подключён к обоим интерфейсам.
- Единый API `userInput` / `updateCurrentState` и общие структуры данных в `src/interface.h`.
- Формализация логики через конечный автомат; диаграммы состояний приложены
  (`src/state_machine_snake.png`, `src/state_machine_tetris.png`).
- Unit-тесты модели «Змейки» на GTest (`src/tests/tests.cc`).
- Сборка через `Makefile` со стандартными целями, проверка стиля по Google Style (clang-format).

## Архитектура

### Разделение по слоям (MVC)

- **Модель** — класс `s21::GameModel` (плюс вспомогательный `s21::Snake`). Хранит состояние игрового
  поля, змейки, яблока, очков и уровня; реализует всю бизнес-логику. Не знает ни о ncurses, ни о Qt.
- **Контроллер** — тонкая прослойка между вводом пользователя и моделью. Для каждого интерфейса —
  свой контроллер, оба работают с одной и той же моделью.
- **Представление** — только отрисовка и ввод: `GameView` (ncurses) в консоли и класс `view` (Qt) на
  десктопе. Бизнес-логики в представлениях нет.

Общий контракт между слоями задаётся структурами из `src/interface.h`:

- `GameInfo_t` — снимок состояния игры (поле `field`, `next`, `score`, `high_score`, `level`,
  `speed`, `pause`);
- `UserAction_t` — перечисление действий пользователя (`Start`, `Pause`, `Terminate`, `Left`,
  `Right`, `Up`, `Down`, `Action`);
- размеры поля `FIELD_WIDTH = 10`, `FIELD_HEIGHT = 20`.

### Модель игры

`s21::GameModel` инкапсулирует состояние и предоставляет узкий интерфейс доступа:

- инициализация и движение: `initSnake()`, `moveSnake(dx, dy)`, `respawnApple()`;
- геттеры состояния: `getHead()`, `getTail()`, `getApple()`, `getEatenApples()`, `getSpeed()`;
- очки/уровень/рекорд: `getLevel()`, `increaseLevel()`, `getHighScore()`, `setHighScore()`,
  `setScore()`, `setLevel()`, `setSpeed()`;
- условие победы: `isGameWon()`;
- синхронизация с общей структурой: `setGameInfo(GameInfo_t*)`.

Змейка представлена головой `snake_head_` и хвостом `snake_tail_` (`std::vector<Snake>`). Стартовая
скорость таймера — 350 мс, начальный уровень — 0.

### Контроллеры

- **Консоль** (`GameController`, `src/gui/cli/s21_snake_controller.*`): содержит `GameModel` и
  `GameView`, реализует `userInput()`, чтение клавиш `userKeyPress()`, главный цикл `run()` и
  `gameOver()`. Направление движения хранится в `dx`/`dy`.
- **Десктоп** (`s21::SnakeController`, наследник `QWidget`): получает указатель на `GameModel`,
  использует `QTimer` для автодвижения, обрабатывает `keyPressEvent`, отрисовывает поле в
  `paintEvent`. Аналогичный контроллер сделан для «Тетриса» (`s21_tetris_controller.*`).

Контроллеры тонкие: они транслируют ввод в вызовы методов модели и запрашивают у неё состояние для
перерисовки.

### Представления

- **Консольное** (`GameView`): отрисовка поля и рамок средствами ncurses (`showMap`), экран победы
  (`showWinScreen`), загрузка и сохранение рекорда (`loadHighScore`, `saveHighScore`).
- **Десктопное** (Qt): главное окно с меню выбора игры (`view` + `view.ui`), боковая панель со
  счётом, рекордом и уровнем (`s21_help_field`).

## Конечный автомат

Логика обеих игр формализована через конечные автоматы. Действия пользователя (`UserAction_t`)
выступают входными сигналами, переходы между состояниями (старт, игра, пауза, завершение) описаны
диаграммами:

- «Змейка» — `src/state_machine_snake.png`;
- «Тетрис» — `src/state_machine_tetris.png`.

## Механика змейки

- Автоматическое движение на один блок вперёд по срабатыванию игрового таймера.
- Поедание яблока увеличивает длину змейки на один сегмент и порождает новое яблоко
  (`respawnApple`).
- Победа при достижении длины 200 «пикселей» (`isGameWon`).
- Поражение при столкновении со стеной или с собственным телом.
- Повороты только влево/вправо относительно текущего направления движения (стрелки).
- Ускорение движения по клавише действия (`Action`).
- Начальная длина змейки — 4 сегмента, поле — 10×20.

## Очки, рекорд и уровни

- **Счёт**: +1 очко за каждое съеденное яблоко.
- **Рекорд**: максимальное значение хранится в файле и сохраняется между запусками
  (`src/high_score_snake.txt` для «Змейки», `src/record.txt` для «Тетриса»). Обновляется в ходе
  игры при превышении текущего рекорда.
- **Уровни**: каждые 5 очков уровень повышается на 1 (`increaseLevel`), максимум — 10; рост уровня
  увеличивает скорость движения змейки.
- Счёт, рекорд и уровень выводятся в боковой панели интерфейса.


## Тестирование

Модель «Змейки» покрыта unit-тестами на GTest (`src/tests/tests.cc`): конструктор, синхронизация
`setGameInfo`, движение `moveSnake`, порождение яблока `respawnApple`, повышение уровня
`increaseLevel`, работа с рекордом и счётом, установка уровня, работа с фигурой. Особое внимание —
состояниям и переходам модели. Запуск: `make test_snake`.
